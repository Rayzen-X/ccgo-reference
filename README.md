# 丛人去哪了 · 在线参考资料

应用固定资料源：

https://raw.githubusercontent.com/Rayzen-X/ccgo-reference/published/reference.json

公开内容只有机场、航班参考资料、状态缩写和发布工具。不存放 Android 源码、安装包、班表截图、姓名或个人行程。

首次版本 2 与应用 1.0.28 的内置参考库一致（87 个机场、170 条航班记录）。这是把维护与下发接通，不表示重新核实了全部时刻，也不是航空公司官方接口。`provenance.json` 明确记录来源说明和核实日期，首次核实日期为空。

## 更新

1. 在 `data/catalog.json` 核实并修改机场、航线、时刻；状态缩写写入 `data/aliases.json`。
2. 更新 `data/provenance.json` 的来源、说明；只有核实了航班资料才能填写核实日期并改为 `reviewed-reference`。
3. 每次修改资料或有效期都递增 `data/release.json` 的 `version`。扩展有效期要求 31 天内的核实日期，流水线不会自动续期旧数据。
4. 执行 `python3 -m unittest discover -s scripts -v` 和 `python3 scripts/publish.py`，提交到 main。GitHub Actions 自动比较线上版本并发布到 published 分支；验证失败时线上文件不变。PR 只验证、不发布。

维护提交保留历史；回滚错误资料时，取回旧内容并以更高版本重新发布，不能降低版本号。每次发布状态可在 Actions 查看；任何失败需要处理，不能宣称持续更新已经完成。

## 手机行为

应用 1.0.29 默认连接固定地址，无需密钥；1.0.28 可手动填入地址。手机后台下载包后检查 schema、SHA-256、版本、有效期和资料格式，失败继续使用本地库。支持手动检查、导入包和清空地址停用。GitHub 的访问速度取决于手机所在网络，离线识别不等待资料下载。

资料更新只影响参考资料及状态文字映射。网格、颜色、字体和识别算法更改仍需要更新 APK。参考时刻不能作为实际起降保证；权威依据为航空公司正式班表。

这套流程自动完成已审核资料的校验与下发，不自动抓取官网、不自动审批数据、不保证未来资料会有人核实。尚未接入稳定的、可用于批量更新的官方航班 API。
